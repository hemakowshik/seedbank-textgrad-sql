Controlled benchmark

18 curated questions across three complexity tiers: (i) single-table retrieval, (ii) filtering and aggregation, (iii) multi-table joins or combined conditions. Each has a hand-written gold SQL query. Execution accuracy compares the predicted query's result with the gold result: same number of rows, and every gold column matched by a predicted column with the same values (row order and extra columns are ignored). TextGrad never sees the gold query; its loss comes only from execution feedback and an LLM evaluator.

How TextGrad is applied here

TextGrad (Yuksekgonul et al., 2024) treats a pipeline of LLM calls like a computation graph. Text variables flow forward; an LLM evaluator produces a textual loss; an LLM writes natural-language gradients (criticism aimed at a specific variable); and a Textual Gradient Descent (TGD) optimizer rewrites the variable. In SeedSQL the optimized variable is the system prompt given to the SQL generator.

TextGrad conceptIn SeedSQL
Variable (requires_grad)The generator's system prompt (instructions). Iteration 1 starts from exactly the zero-shot prompt, so any difference from the zero-shot baseline comes only from refinement.
Forward passprompt + schema + question → LLM → SQL → SQLite execution (read-only, PRAGMA query_only)
LossAn LLM evaluator reads the question, SQL and execution feedback (error text, or columns, row count and sample rows) and writes a critique ending in VERDICT: PASS/FAIL. It never sees the gold query.
Backward (∂loss/∂prompt)An LLM turns the critique into feedback aimed at the prompt variable: what the prompt should say differently.
Optimizer step (TGD)An LLM rewrites the prompt using that feedback and returns it inside <IMPROVED_VARIABLE> tags.
Stopping conditionThe query executes and the evaluator returns PASS, or the iteration limit is reached.
Instance vs prompt levelBy default the prompt is optimized per question (instance-level). With "carry the optimised prompt" on, the prompt keeps improving across questions, and the optimizer is told to keep its rules general (prompt-level).

Assumptions (demo)

Retest threshold 75% germination. Recommended storage: ≤15 °C and ≤50% RH. Viable stock: quantity > 0 and the latest germination ≥ 75%. These thresholds are stated in the questions, not in the prompt.

Scope & limitations

  • Decision support only: the system summarises records. It doesn't make agricultural decisions.
  • Synthetic prototype data: a small controlled database, and results depend on schema quality and data completeness.
  • Execution ≠ correctness: a query can run and still be wrong, which is why execution accuracy is checked against gold results.
  • Evaluator noise: the LLM loss can reject a correct query (wasting iterations) or accept a wrong one. Benchmark traces show where this happens.
  • Results are measured, not assumed: run the benchmark and report what you observe, including where refinement doesn't help.
